# Mimir 0.7.0 — Import an Existing Project Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command that reads a project folder — git repo or plain directory — and loads the durable knowledge in it into Mimir, so an agent's first session starts informed instead of empty.

**Architecture:** A small CLI inside the existing `@mojoaar/opencode-mimir` package (`npx @mojoaar/opencode-mimir ingest .`). It walks a directory, picks documentation and configuration rather than source code, splits the result into batches the server already accepts (100 files / 2 MB), and posts each batch through the existing `memory_ingest` MCP tool. Git is used only to *name* the project; a folder with no repo gets an explicit slug, which needs one small service change so a named project can be created on first import.

**Tech Stack:** TypeScript compiled by `tsc` (the package already builds to `dist`), `node:fs`, `node:path`, `node:child_process` (`git remote get-url`), no new runtime dependencies, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-25-mimir-design.md` (§8 memory model, §10 learning pipeline, §14 agent support). §23 lists server-side cloning as deferred; this plan is the agent-side walker that decision left room for.

## Global Constraints

- The walker runs on the client. Mimir never sees the repository, needs no credentials for it, and the server gains no filesystem access.
- Nothing is sent that the user did not ask for: the default selection is documentation and configuration, `--all` is opt-in, and `--dry-run` prints exactly what would be sent.
- A batch never exceeds 100 files or 2 MB, because the server refuses one that does (and refuses the whole batch, not the overflow).
- Each file is capped at 256 KB (`MAX_BODY_BYTES`); an oversized file is reported and skipped, never truncated silently.
- Memory paths stay valid: every imported file lands under `import/` and is normalised by the server, so a filename with spaces, unicode or punctuation must not lose the file — the plan's first review focus.
- No new dependency in the package: argument parsing is 30 lines, globbing is a hand-written matcher, and the tests are the only place that needs a fixture tree.
- The package's version is aligned to the release (`0.4.0` → `0.7.0`) so the CLI ships with the same tag that carries the rest.
- Release is `0.7.0`: MINOR, because the CLI is additive.

## Review Focus

1. **An awkward filename still gets imported.** `docs/Ærø Skibsfart.md`, `Notes (draft).md` and a name with a `#` must either land under a normalised path or be reported as skipped with a reason — never silently vanish while the run reports success.
2. **A big file does not take the batch with it.** One 400 KB file in a folder of small ones is skipped and named; the other files still land, and the exit code says something was skipped.
3. **A large repo still imports completely.** 250 files become three batches, not one rejected request, and the final count equals what the walk selected.
4. **A folder that is not a repository lands in a project the user asked for.** `--project notes` creates `notes` on first run and reuses it on the second; two different folders both called `docs` do not merge into one project.
5. **Nothing is sent when the user said not to.** `--dry-run` performs no network call and exits 0; a bad token exits non-zero, names the failure and writes nothing.

### Task 2: Decide what to send

**Files:**
- Create: `packages/opencode-plugin/src/select.ts`, `packages/opencode-plugin/test/select.test.ts`
- Test: `packages/opencode-plugin/test/select.test.ts`

**Interfaces:**
- Produces:
  - `type WalkOptions = { all?: boolean; maxFileBytes?: number }`.
  - `type WalkEntry = { path: string; bytes: number }` (`path` is relative, `/`-separated).
  - `type WalkResult = { files: WalkEntry[]; skipped: { path: string; reason: string }[] }`.
  - `selectFiles(root: string, options?: WalkOptions): Promise<WalkResult>`.
  - `IGNORED_DIRS` (`node_modules`, `.git`, `dist`, `build`, `.next`, `coverage`, `.venv`, `venv`, `__pycache__`, `.idea`, `.vscode`, `vendor`, `target`, `tmp`) and `IGNORED_EXTENSIONS` (binaries: `png jpg jpeg gif webp ico pdf zip gz tar bz2 7z rar exe dll so dylib o a class jar wasm mp3 mp4 mov avi woff woff2 ttf eot`) exported for the test.

Selection rules, in order:
1. Skip a path whose directory is in `IGNORED_DIRS`.
2. Skip `IGNORED_EXTENSIONS`.
3. Skip a file larger than `maxFileBytes ?? 262144`, recorded in `skipped` with `too large (<n> bytes)`.
4. Docs mode (`all !== true`) keeps a file only when it matches: basename starts `readme`, `changelog`, `contributing`, `license` (case-insensitive) at depth ≤ 1; any file under `docs/` or `doc/`; any `*.md`/`*.mdx` at depth ≤ 3; or the basename is in `CONFIG_FILES` (`package.json`, `tsconfig.json`, `docker-compose.yml`, `docker-compose.yaml`, `compose.yml`, `compose.yaml`, `Dockerfile`, `Makefile`, `pyproject.toml`, `go.mod`, `Cargo.toml`, `.env.example`, `renovate.json`, `turbo.json`) at depth ≤ 2.
5. `all: true` keeps everything that survived 1–3.

Files that are excluded by 4 are simply not listed (that is the point of the default), while files excluded by 3 are listed in `skipped` (the user asked for them and did not get them).

### Task 4: The command

**Files:**
- Create: `packages/opencode-plugin/src/cli.ts`, `packages/opencode-plugin/test/cli.test.ts`
- Modify: `packages/opencode-plugin/package.json` (`bin`, `version` 0.7.0), `packages/opencode-plugin/README.md`
- Test: `packages/opencode-plugin/test/cli.test.ts`

**Interfaces:**
- Consumes: `parseArgs` (Task 3), `selectFiles` (Task 2), `batchFiles` (Task 3), `callTool` and `detectRepo` (`src/client.ts`), `memory_ingest`.
- Produces: `runIngest(args: IngestArgs, io: { out: (line: string) => void; err: (line: string) => void; cwd: string; env: Record<string, string | undefined>; root?: string }): Promise<number>` — returns the exit code, never calls `process.exit` (so it is testable), and `main(argv: string[]): Promise<void>` which wires `process` and sets `process.exitCode`.

Flow:
1. `--help` or no arguments → usage text, exit 0.
2. Resolve the root (`path.resolve(io.cwd, args.path)`); a missing directory prints `no such directory: <path>` and exits 2.
3. Choose the project key: `--project` wins and is sent as `project`; otherwise, when `detectRepo(root)` finds a git remote, send that as `repo`; otherwise send `project: path.basename(root)`. This matters more than it looks: a git repository must land in the project the agents will already write to (`X-Mimir-Repo`), or the import would sit in a sibling project nobody reads. `--url` and `--token` default to `MIMIR_URL` / `MIMIR_TOKEN`.
4. `selectFiles(root, { all })`, then read each file as UTF-8 (a file that fails to read is moved to `skipped` with the error message, not fatal).
5. `--dry-run` prints `would import N files (M bytes) into <project|repo> as import/<path>` plus any skipped, exits 0, and makes **no** call.
6. Otherwise for each batch: read the bodies, `callTool('memory_ingest', { ...key, path_prefix: 'import', files }, { timeoutMs: 60_000 })`. A failed batch prints `batch <n> failed: <error>` and continues with the rest; failures are counted.
7. Summary: `imported X files, skipped Y (see above)`; exit 0 when every batch succeeded, 1 when any failed, 1 when `skipped` is non-empty, 0 when `--dry-run`.

`package.json`: `"bin": { "mimir": "./dist/cli.js" }`, `"version": "0.7.0"`, and `cli.ts` starts `#!/usr/bin/env node` so the published file is executable (tsc preserves it).

## Out of scope, and why

- **`--learn` (model-written summaries of a repo).** The extraction pipeline already gives every imported memory a model-written title and summary when the project has learning on, so a second summariser would duplicate it. What `--learn` was meant to add — reading the code and writing *semantic* memories (`conventions/testing`, `gotchas/migrations`) — is the deferred consolidation job, which needs real data to choose a merge policy. Running `mimir ingest .` followed by enabling learning gets most of the value today.
- **`.gitignore` parsing.** The default selection never reads source at all, and `--all` is an explicit "send everything" that a user can scope with a subdirectory. A partial gitignore implementation that disagrees with git is worse than none.
- **Server-side cloning.** Deferred in the spec, and it would put repository credentials on the server.
