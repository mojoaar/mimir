# 0.11.0 Language — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every screen a signed-in person uses can be read in English, Danish or German, chosen from the app header and remembered on the account.

**Architecture:** Strings stay in the existing flat catalogs (`lib/i18n/messages/{en,da,de}.ts`) under an `app.*` prefix. Server components and server actions resolve the locale once per request (`users.locale` → `mimir_locale` cookie → `Accept-Language` → English) and translate on the server, so client components receive finished strings as props and no i18n runtime ships to the browser. The app locale is **not** in the URL: marketing keeps `/da` and `/de`, the product area stays on one path with the preference on the account.

**Tech Stack:** Next.js 16 App Router, TypeScript, the hand-rolled i18n in `lib/i18n`, Postgres `users.locale`.

**Spec:** `docs/superpowers/specs/2026-10-25-mimir-design.md` (§16 i18n, §17 UI).

## Global Constraints

- Only theme alias classes (`bg-[var(--bg)]`, `text-[var(--text-muted)]`, …). No palette classes; `styles/theme.test.ts` fails the build if one appears.
- Every product page keeps `export const instant = false`.
- A `'use server'` module may export only async functions; types and non-exported constants are fine.
- `redirect()` calls sit outside `try` blocks.
- Danish and German must read like a person wrote them. No literal calques of English word order, no "Mimir" in lower case, no machine-ese.
- Never translate: repo keys, memory paths, email addresses, ISO timestamps, tool names (`memory_write`), provider preset ids (`opencode_go`), the MIT licence name, `v0.11.0`.
- A translated `ok`/`error` string is always produced on the server. Client components never call the catalog.
- Key naming: `app.<area>.<thing>` (e.g. `app.nav.projects`, `app.login.submit`). Marketing keys keep their existing unprefixed names.
- Tests assert English by default (English is the fallback in the test environment) and **one Danish string per task**, which is what proves the catalog is wired rather than duplicated in JSX.
- Test commands: `npm test`, `npm run test:int` (dev Postgres on 127.0.0.1:5433), bare `npm run typecheck` (never piped).

## Review Focus

1. **A key that exists only in English.** A missing Danish or German entry must fall back to English text, never render `app.teams.leave` to a person. Test: `t('da', 'app.only.in.english')` returns the English sentence; the catalogs' key sets are asserted equal.
2. **A stale language after switching.** The next page load must be in the new language on its first paint, with no flash of English. Test: the layout renders Danish server-side when `users.locale` is `da`.
3. **Who wins.** A signed-in user's stored choice must beat the browser's `Accept-Language`; a visitor who is not signed in still gets their browser's language. Test: both directions.
4. **Translating changes nothing else.** A Danish user sees the same projects, the same permissions and the same data. Test: the dashboard renders under `da` with the same project names.
5. **Placeholders.** `{email}`, `{name}`, `{count}` must be substituted, and a placeholder missing from a translation must not print raw braces. Test: `t('da', key, {email})`, and a translation that forgot its placeholder is caught by a catalog test.

export type Translate = (key: string, vars?: Record<string, string | number>) => string

`translator()` = `const locale = await getRequestLocale(); return (key, vars) => t(locale, key, vars)`.

## Self-review notes

- **Spec coverage:** §16 asks for en/da/de, cookie → `Accept-Language` → en, missing-key fallback logged in development, and `users.locale` driving the user's experience. Task 1 covers resolution and fallback, Task 2 the control and persistence, Tasks 3–7 the screens, Task 8 the drift guard. Emails localised from `users.locale` are **not** in this plan — `lib/email/templates.ts` is still English; ledger it as deferred.
- **Docs stay English** (§16 decision, restated in Task 8's docs paragraph), so no docs translation work.
- **Type consistency:** `translator()` returns `Translate` used identically in every task; `labels` props are named the same way across components; `app.error.<code>` is one shared namespace for `forbidden`, `invalid_params`, `not_found`, `rate_limited`, `body_too_large`, `invalid_path`, plus `app.error.generic`.
- **Proportion:** eight tasks, one screen group each, no shared abstraction invented beyond `translator()` and the `labels` prop convention.
