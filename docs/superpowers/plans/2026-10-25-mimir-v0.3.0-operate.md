# Mimir 0.3.0 — Operate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Mimir safe to run for real: encrypted scheduled backups to S3 or WebDAV/pCloud, admin user management with working revocation, TOTP MFA, an optional IP allowlist, an audit viewer with a retention prune, and a stats dashboard.

**Architecture:** Everything is a service module under `lib/` with thin route handlers, server actions and one admin page per surface, following the pattern 0.1.0/0.2.0 established. Backups are one pg-boss job that produces two encrypted artifacts, uploads them through a small `Storage` interface with two implementations, verifies by `HEAD`, and prunes by name. Settings gain typed accessors so no page reads raw JSON. MFA adds a two-step login. The allowlist is a pure matcher plus a cached settings read enforced at every request entry point.

**Tech Stack:** Next.js 16 App Router, TypeScript strict, Tailwind v4, Postgres 18 + pgvector 0.8, pg-boss 12, `aws4fetch` (S3 SigV4), `otpauth` (TOTP), `qrcode` (SVG), Resend over plain `fetch`, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-25-mimir-design.md` (§12 auth and accounts, §18 backups, §19 audit, §20 deployment, §21 security posture). Read the spec alongside this plan: it is the authority when the two disagree.

## Global Constraints

- Node 22 in the image, Node 26 locally. TypeScript strict with `noUncheckedIndexedAccess`.
- `MIMIR_SECRET` is never generated. It keys provider credentials, settings secrets and backups.
- Every audit row has a namespaced action, and `detail` never contains a secret, a key, a token or a memory body.
- Backups are AES-256-GCM, key derived with HKDF `info="mimir/backup"`, and a backup is not recorded `ok` until its uploaded size has been verified.
- Admin pages live under `/app/admin/*` and are gated by `requireAdmin()`. Per-user pages live under `/app/settings/*`.
- Dynamic pages declare `export const instant = false`; server actions live in `actions.ts` with `'use server'`; client forms live in their own `.tsx` with `useActionState`.
- Styling uses only the theme alias variables (`--bg`, `--bg-raised`, `--border`, `--accent`, `--accent-fg`, `--danger`, `--text-muted`, `--fg`). No Tailwind palette classes; `styles/theme.test.ts` fails the build if any appear.
- Tests: `npm test` (unit) and `npm run test:int` (integration, needs `./scripts/test-db.sh up`). `npm run typecheck` runs bare, never piped.
- A migration is applied exactly once and is never edited after it ships. New columns and indexes go in `0003_operate.sql`.
- SemVer: this release is `0.3.0`. Breaking changes bump the minor before 1.0 and are marked `BREAKING` in the changelog.
- The database runs PostgreSQL 18 (`pgvector/pgvector:pg18`, pgvector 0.8.7). The container image installs `postgresql18-client`, because `pg_dump` refuses a server newer than itself and the backup job would fail silently at 3 a.m.
- The database has no `pg_dump` on a developer machine, so dump code is tested through an injected runner; the real binary is proven in the release task inside the container.

## Review Focus

1. **A backup that fails part-way** (upload ok, `HEAD` mismatch, listing error, provider down) records `failed` with the reason, keeps the previous good backups, and never leaves a row that says `ok` for an object that cannot be restored.
2. **An admin cannot lock the install out**: the last admin cannot be demoted, disabled or deleted, an admin cannot disable or delete themselves, and `require_mfa` never strands the bootstrap admin from env vars.
3. **Disabling a user ends access immediately**: live sessions and API keys stop working on the next request, not at the next login, and the revocation happens in the same transaction as the status change.
4. **A wrong, expired or replayed TOTP code never creates a session**, and an unconfirmed enrolment secret cannot be used to log in.
5. **The IP allowlist cannot be bypassed** with a forged `X-Forwarded-For`, applies to an already-valid session, and never locks `/health` out.

### Task 4: Admin user service with revocation that actually works

**Files:**
- Create: `lib/users/service.ts`
- Test: `lib/users/service.int.test.ts`

**Interfaces:**
- Consumes: `withAdmin`, `revokeAllSessions(userId, tx)`, `hashPassword`, `audit`.
- Produces:

  - `type AdminUser = { id, email, name, role, status, mfaEnabled, lastLoginAt: Date | null, createdAt: Date, projectCount: number }`.
  - `listUsers(input: { query?: string; status?: UserStatus; limit?: number; offset?: number }): Promise<{ rows: AdminUser[]; total: number }>` — `query` matches `email` or `name`, case-insensitively.
  - `getUser(userId: string): Promise<AdminUser | null>`.
  - `verifyUser(actorId, userId)`, `enableUser(actorId, userId)`, `disableUser(actorId, userId)`.
  - `createUser(actorId, input: { email: string; name: string; role: UserRole; password?: string }): Promise<{ id: string; inviteToken: string | null }>` — always `active`; `inviteToken` is returned when no password was given.

  - `resetMfaForUser(actorId, userId)`.

- `disableUser` and `deleteUser` refuse the caller's own id (`forbidden`, `'You cannot disable your own account.'` / `'You cannot delete your own account.'`).

- `resetMfaForUser` clears `totp_secret_enc` and `totp_pending_enc`, sets `totp_last_step = null`, and revokes sessions in one transaction.
- Every mutation writes one audit row: `admin.user_verify`, `admin.user_enable`, `admin.user_disable`, `admin.user_create`, `admin.user_role_change`, `admin.mfa_reset`, `admin.user_delete`, with `targetType: 'user'` and `targetId` the user id and no email in `detail`.

### Task 6: TOTP service with a replay guard

**Files:**
- Create: `lib/db/migrations/0003_operate.sql`, `lib/auth/mfa.ts`
- Test: `lib/auth/mfa.int.test.ts`

**Interfaces:**
- Consumes: `sealSecret`/`openSecret` (Task 1), `withAdmin`, `audit`, `getConfig().publicUrlSeed` for the issuer.
- Produces:
  - `type Enrollment = { secret: string; uri: string }`.
  - `beginEnrollment(userId: string): Promise<Enrollment>` — writes `totp_pending_enc` only; does not enable MFA.
  - `confirmEnrollment(userId: string, code: string): Promise<{ ok: true } | { ok: false; reason: 'invalid_code' | 'no_pending' }>` — verifies against the pending secret, then moves it to `totp_secret_enc`, clears `totp_pending_enc`, and sets `totp_last_step`.
  - `verifyMfaCode(userId: string, code: string): Promise<{ ok: true } | { ok: false; reason: 'invalid_code' | 'replayed' | 'not_enrolled' }>` — window ±1 step, rejects a step `<= totp_last_step`, and stores the accepted step.
  - `mfaEnabled(userId: string): Promise<boolean>` — `totp_secret_enc is not null`.
  - `disableMfaForUser(userId: string): Promise<void>` — self-service off; refuses under `require_mfa` with `{ code: 'forbidden' }`.
  - `mfaUri(secret: string, email: string, issuer: string): string` — `otpauth://totp/<issuer>:<email>?secret=…&issuer=…&digits=6&period=30`.

Migration `0003_operate.sql`:

```sql
alter table users add column if not exists totp_pending_enc bytea;
create index if not exists audit_log_created_idx on audit_log (created_at desc);
create index if not exists audit_log_action_created_idx on audit_log (action, created_at desc);
```

(The two indexes serve the audit viewer in Task 12; they ship here because this is the release's only migration.)
