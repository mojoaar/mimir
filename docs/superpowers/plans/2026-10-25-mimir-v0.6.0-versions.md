# Mimir 0.6.0 — Versioned Memory Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every write keeps what it replaced, so an agent that overwrites a memory can be inspected, diffed and undone from the browser.

**Architecture:** A `memory_versions` table under the same row-level security as `memories`. `writeMemory` archives the row it is about to replace inside the same transaction, taking a row lock first so two concurrent writers cannot both archive the same older body and lose the body between them. The browser gains a history panel with a line diff and a restore button; a restore is an ordinary write, so it archives the pre-restore content and can itself be undone. Versions are pruned to the newest 20 per memory by the existing nightly purge job.

**Tech Stack:** Next.js 16 App Router, TypeScript strict, Tailwind v4, Postgres 18 + pgvector, pg-boss 12, `diff` (new dependency, for the line diff), Vitest.

**Spec:** `docs/superpowers/specs/2026-10-25-mimir-design.md` (§8 memory model, §9 retrieval, §19 audit). The spec's §23 lists memory versioning as deferred; this plan is that release.

## Global Constraints

- A migration is applied once and never edited afterwards. This release adds `0004_versions.sql` and nothing else.
- Every tenant-scoped table carries row-level security. `memory_versions` is visible through the same `can_access_project()` predicate as `memories`, and insertable only through `can_write_project()`.
- Versions are immutable: no `UPDATE` grant to `mimir_app`, no update path in the service.
- Nothing in the write path may fail because archiving failed; a version insert is part of the memory write transaction, so it either lands with the write or the write does not happen. (This is the one place where "never fail the write" does not apply — losing history silently is worse than a 500 the agent can retry.)
- Audit stays in the adapters: one `memory.restore_version` row per restore request, detail `{via}`, never a body.
- Styling uses only the theme alias variables. No Tailwind palette classes; `styles/theme.test.ts` enforces it.
- Dynamic pages declare `export const instant = false`; server actions live in `actions.ts` with `'use server'`; client forms live in their own `.tsx`.
- Tests: `npm test` and `npm run test:int` (dev database on `127.0.0.1:5433` via `./scripts/test-db.sh up`). `npm run typecheck` bare, never piped.
- Release is `0.6.0`: MINOR, because it adds a table and two endpoints without changing an existing one.

## Review Focus

1. **Two writers on one path never lose a version.** Whichever order they commit in, the bodies archived are exactly the ones that were overwritten — no duplicate archive of the same body, and no body that vanishes between them.
2. **A re-write with an unchanged body makes no history.** Twenty agents re-asserting the same fact must not bury the interesting change under twenty identical rows.
3. **Restore is undoable.** Restoring an old version archives the content it replaced, so a mistaken restore is itself in the history.
4. **No version leaks across projects or grants.** A version id from another project returns not-found, and a read grantee sees history but cannot restore.
5. **Pruning is bounded and safe.** It never removes the newest 20 of a memory, never touches another memory's rows, and a purged memory takes its versions with it.

### Task 1: Record a version on every change

**Files:**
- Create: `lib/db/migrations/0004_versions.sql`, `lib/memory/versions.ts`
- Modify: `lib/memory/service.ts` (`writeMemory`)
- Test: `lib/memory/versions.int.test.ts`, plus two cases added to `lib/memory/service.int.test.ts`

**Interfaces:**
- Consumes: `withUser`, `requireProjectRole`, `normalisePath`, the existing `memories` upsert.
- Produces:
  - `VERSION_LIMIT = 20` (exported from `lib/memory/versions.ts`).
  - `type MemoryVersion = { id: string; path: string; title: string; summary: string | null; body: string; kind: string; source: string; updatedAt: Date; createdAt: Date }`.
  - `type VersionSummary = Omit<MemoryVersion, 'body' | 'summary'> & { bytes: number }`.
  - `listVersions(userId: string, projectId: string, path: string, limit?: number): Promise<VersionSummary[]>` — newest first, default `VERSION_LIMIT`, capped 1–100. `bytes` comes from `length(body)` in SQL, so the body itself never leaves the database for a list.
  - `getVersion(userId: string, projectId: string, versionId: string): Promise<MemoryVersion | null>`.
  - Both call `requireProjectRole(userId, projectId, 'read')` first, so a stranger gets `forbidden` rather than quietly an empty list.
  - `archivePrevious(tx: PoolClient, input: { projectId: string; path: string }): Promise<string | null>` — internal to `writeMemory`: locks and returns the row id it archived, or null.

Migration:

```sql
create table memory_versions (
  id bigserial primary key,
  memory_id uuid not null references memories (id) on delete cascade,
  project_id uuid not null references projects (id) on delete cascade,
  path text not null,
  title text not null,
  summary text,
  body text not null,
  kind text not null,
  source text not null,
  updated_at timestamptz not null,
  created_at timestamptz not null default now()
);

create index memory_versions_path_idx
  on memory_versions (project_id, lower(path), created_at desc);

alter table memory_versions enable row level security;

create policy memory_version_read on memory_versions
  for select using (can_access_project(project_id));

create policy memory_version_write on memory_versions
  for insert with check (can_write_project(project_id));

grant select, insert, delete on memory_versions to mimir_app;
grant usage, select on sequence memory_versions_id_seq to mimir_app;
```

`writeMemory` change: inside the existing `withUser` transaction, **before** the upsert:

```ts
const previous = await tx.query<{ id: string; body: string; deleted_at: Date | null } & Record<string, unknown>>(
  `select id, title, summary, body, kind, source, updated_at, deleted_at
     from memories
    where project_id = $1 and lower(path) = lower($2)
      for update`,
  [input.projectId, path],
)
```

then the upsert as today, then, when `previous.rows[0]` exists, `deleted_at` is null **and** its body differs from `input.body`, insert the archived row. The lock is the point: without `for update`, two concurrent writers both read the same old body, both archive it, and the body written between them is never recorded.

- [ ] **Step 3: Implement the prune and wire it into `runPurge`**

One statement:

```sql
delete from memory_versions v
 using (
   select id, row_number() over (partition by memory_id order by created_at desc, id desc) as rn
     from memory_versions
 ) ranked
 where v.id = ranked.id and ranked.rn > $1
```

**Interfaces:**
- Consumes: `listVersions`, `getVersion` (Tasks 1–2), `restoreVersionAction` (this task), the `page.tsx` reader.
- Produces: `HistoryPanel({ projectId, slug, path, currentBody, canWrite, versions, selected, diff })` — a server component; `type DiffLine = { kind: 'same' | 'add' | 'remove'; text: string }` and `diffLines(before: string, after: string): DiffLine[]` exported for its test.

When `history=1`, `listVersions` runs alongside the tree; when `version` is present, `getVersion` and `diffLines(version.body, current.body)` are computed server-side with `diffLines` from the new `diff` dependency, rendered as `<pre>` rows prefixed `+ `, `- ` or `  ` and coloured with `--accent` / `--danger` / `--text-muted`.

Layout: the reader gains a `History (N)` link beside `kind · updated`. Restore is a plain form posting to the new `restoreVersionAction`, shown only when `canWrite`; success redirects to `?path=…&history=1` with a notice.
