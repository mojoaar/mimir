# 0.10.1 — App navigation and footer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the signed-in app a properly padded header with Admin and Docs links, and a shared footer, matching the admin and docs layouts.

**Architecture:** One shared `components/app/footer.tsx` rendered by both the app and docs layouts; the app header is restructured to the admin header's shape (full-width border, inner `mx-auto` container) and gains a role-gated Admin link plus a Docs link. Pure presentation — no service, database, or action changes.

**Tech Stack:** Next.js 16 App Router, TypeScript strict, Tailwind v4 theme aliases, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-25-mimir-design.md` (§17 UI/theming).

## Global Constraints

- Theme aliases only (`--fg`, `--bg-raised`, `--border`, `--text-muted`, `--accent`, …); never a palette class. `styles/theme.test.ts` scans `app/**/*.tsx` and fails on palette classes.
- The marketing footer (`app/[locale]/page.tsx`) is i18n-driven and is NOT touched; the shared footer only goes into the app and docs layouts.
- Version shown in the footer must come from `package.json` (import the JSON), never a hardcoded string — it must not rot on the next bump.
- `npm run typecheck` and `npm test` must stay green; there are no integration changes.

## Review Focus

1. **The Admin link is role-gated.** A non-admin signed-in user must not see or reach `/app/admin`; `requireAdmin` must still redirect. → Task 1 test renders the header for a `user` and asserts no `/app/admin` link.
2. **The footer appears on the app and docs, but not the marketing page.** → Task 2 tests assert the footer renders in both layouts; the marketing page test still sees its own i18n footer and no duplicate.
3. **The footer version always equals `package.json`.** → Task 2 test pins the rendered version against `pkg.version`.
4. **No palette class sneaks into the new footer/header.** → Task 2 test (or the existing `styles/theme.test.ts` scan) fails on `bg-white`/`text-red-500`-style classes.
5. **Existing nav still works.** The header keeps Projects/Teams/Settings/Providers and the email/theme switcher; a page test that renders the layout still finds them. → Task 1 test asserts all five links plus the email still render.

### Task 2: Shared footer in the app and docs layouts

**Files:**
- Create: `components/app/footer.tsx`
- Modify: `app/(product)/app/layout.tsx` (append the footer after `children`/the forced block), `app/docs/layout.tsx` (append after the body div)
- Test: `components/app/footer.test.tsx` (new)

**Interfaces:**
- Produces: `AppFooter` — a default-exported server component with no props, reading `pkg` from `../../package.json`.

- [ ] **Step 1: Write the failing tests**

`components/app/footer.test.tsx` renders `AppFooter` with `renderToStaticMarkup` and asserts it contains: `Crafted with`, `Morten Johansen`, `https://github.com/mojoaar/mimir`, `MIT`, `href="/docs"`, `v${pkg.version}` (importing `pkg` from `../../package.json`), and `© ${new Date().getFullYear()}`. A second test renders the app and docs layouts (reuse the Task 1 layout mocks) and asserts each contains `Crafted with`.

- [ ] **Step 2: Run to verify they fail**

Run: `npm test -- footer`
Expected: FAIL — `Cannot find module '@/components/app/footer'` / no `Crafted with`.

- [ ] **Step 3: Implement `components/app/footer.tsx` and wire it in**

`AppFooter` returns `<footer className="mt-auto border-t border-[var(--border)]">` wrapping `<div className="mx-auto flex max-w-3xl flex-wrap items-center justify-between gap-3 px-4 py-6 text-sm text-[var(--text-muted)] sm:px-6">` with the line: `Crafted with ❤️ & 🤖 by Morten Johansen · <a href="https://github.com/mojoaar/mimir">GitHub</a> · MIT · <a href="/docs">Docs</a> · v{pkg.version} · © {new Date().getFullYear()}`. Links use `hover:text-[var(--fg)]` and the same focus-visible outline as the docs sidebar. In `app/(product)/app/layout.tsx`, wrap the returned fragment in a `<div className="flex min-h-screen flex-col">` and place `<AppFooter />` after the `children`/`forced` block. In `app/docs/layout.tsx`, add `<AppFooter />` after the `<div className="mx-auto flex max-w-6xl …">` body wrapper (the docs footer keeps `max-w-6xl` to match its own header width — pass no width override; use the same component and let the docs layout keep its own container, so the footer's inner div stays `max-w-3xl`, which is acceptable as a simple centred footer, or note it in the step). Choose: give `AppFooter` no width of its own beyond `mx-auto max-w-6xl px-4 sm:px-6` so it sits well under both layouts' `max-w-6xl`/`max-w-3xl` parents — settle this by using `max-w-6xl` in the footer inner div and accepting it is wider than the app's `max-w-3xl` content, matching the docs header.
