# Mimir 0.9.0 — Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close all sixteen findings from the 0.8.0 audit — one real security hole, three correctness gaps, and twelve pieces of debt — without adding a subsystem.

**Architecture:** Each finding is fixed where it lives. No new service, no new dependency, one new page (forgot password) and one new plugin hook. Three changes are behavioural and need tests at the service boundary: the provider URL guard, the account-keyed throttle, and the single grant-rank SQL fragment. Everything else is deletion, renaming, or a smaller version of what is already there.

**Tech Stack:** Next.js 16 App Router, TypeScript strict, Postgres 18 + pgvector, pg-boss, Vitest, `@opencode-ai/plugin` (peer dependency of the plugin package).

**Spec:** `docs/superpowers/specs/2026-10-25-mimir-design.md` (§11 providers, §12 auth and rate limits, §9 retrieval/tenancy, §14 agent support, §18 backups).

## Global Constraints

- No new runtime dependency. `@opencode-ai/plugin` is already installed for the plugin package.
- Migrations are additive and numbered: this release needs none (every fix is code).
- A DB error message must never reach a browser or an agent; an audit log entry must never lose the information an operator needs to read it.
- Deleting access must always be possible; adding access must always be validated. When in doubt, refuse the write.
- Anything that reads from the database stays a `withUser` call so RLS applies; `withAdmin` stays reserved for migrations, jobs, fixtures and the bootstrap admin.
- Release is `0.9.0`: MINOR, because three findings are small features (plugin injection, team leave/rename, forgot password).
- `npm run lint` still fails on pre-existing errors in files this plan does not touch. Do not make it worse; do not make fixing it scope.

## Review Focus

1. **A provider URL pointed at the host itself is refused, and the documented local providers still work.** `http://127.0.0.1:5432`, `http://169.254.169.254`, `http://10.0.0.5` and `file:///etc/passwd` are rejected with a message that says why; `http://host.docker.internal:11434`, `http://ollama:11434` and a public `https://api.deepseek.com` are accepted.
2. **Brute force still stops when the proxy is misconfigured or the process restarts.** The account lock is the backstop that survives both; the in-process throttle must not pretend to have an IP dimension it does not have, and five wrong passwords must lock the account even when every attempt claims a different address.
3. **The three grant-rank sites agree.** A project shared with one team for `write` and another for `read` answers `write` from `projectRole`, `resolveProject`, `getProject` and `listProjects` — the same answer from every path, including a stranger receiving `null`.
4. **Leaving a team is not a way to take access from someone else.** A member leaving keeps every other member's access; the last owner cannot leave; a non-member leaving changes nothing.
5. **The plugin never blocks a session and never lies.** The digest injection returns within 1.5 s, adds nothing when Mimir is unreachable or unconfigured, and never throws into the host.

## Rulings made in this plan

- **The rate limiter stays in-process.** Moving it to Postgres would add a write to every login for a lock the database already provides. The fix is honesty plus an account key.
- **`last_used_at` is kept.** "Last used" is what tells you which key to revoke first; only the `await` goes.
- **The 404 task may end in a documented panel rather than a status code.** Next 16 streams a dynamic route's shell before `notFound()` resolves; the plan tries the two cheap ways to prevent that and then tells the truth instead of claiming a status the router cannot send.
- **Teams rename changes the name only.** The URL carries the team id since 0.8.0, so a rename cannot break a link.
- **Password reset reuses `deliverToken`.** No second token type, no new email template.

## Out of scope

- Per-team roles beyond owner/member, and any "what does this team see" overview.
- Moving the rate limiter to Postgres, or multi-replica support.
- `npm run lint`'s pre-existing errors.
- Consolidation, server-side cloning, WebAuthn, per-project embedding models, hosted tier.
