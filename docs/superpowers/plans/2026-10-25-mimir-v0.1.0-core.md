# Mimir v0.1.0 Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.1.0 — Mimir boots from one container, authenticates a user, and stores and retrieves project memory through MCP.

**Architecture:** One Next.js App Router process serving UI, `/mcp` and `/api/v1`. Domain logic lives in plain TypeScript modules under `lib/`; route handlers and the MCP endpoint are thin adapters. Postgres 17 + pgvector holds everything, with RLS forced on the four data tables and a non-owner runtime role.

**Tech Stack:** Next.js 16 (App Router, TypeScript strict), Postgres 17 + pgvector, `@node-rs/argon2`, `otpauth`, Tailwind v4, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-25-mimir-design.md`

## Global Constraints

- Node 22, npm, no lockfile churn beyond `npm install`.
- Next.js 16 App Router. Pin the exact version that `create-next-app@16` installs and record it in `CHANGELOG.md`.
- TypeScript `strict: true`. No `any` in `lib/`; `unknown` + narrowing instead.
- Postgres 17 via `pgvector/pgvector:pg17`. Extensions `vector` and `citext`.
- Two roles: `mimir_owner` (migrations only) and `mimir_app` (runtime). The app never connects as owner at request time.
- `MIMIR_SECRET` is required and never generated. Exactly 64 hex characters (32 bytes). Boot fails with an actionable message when missing or malformed.
- All ids are `uuid` from `gen_random_uuid()`. All times are `timestamptz`.
- Memory body cap 256 KB. Ingest batch cap 100 files / 2 MB.
- Paths stored lowercase, charset `[a-z0-9._/-]`, no leading or trailing slash, no `..`, max 512 characters.
- One path is one memory. Writes upsert. Reads and searches always exclude `deleted_at IS NOT NULL`.
- Every database access goes through `lib/db/tx.ts`. No `pool.query` anywhere else.
- One audit row per MCP or REST call, never per memory touched.
- Secrets never reach logs or `audit_log.detail`; everything passing through `redact()`.
- **pg-boss is not installed in this plan.** It arrives with the first background job in plan 2, so this milestone has no queue and no worker. Nothing in v0.1.0 needs one.
- Unit and integration tests both run under Vitest. Integration tests are the `*.int.test.ts` files and require `MIMIR_TEST_DATABASE_URL`.
- Commits are conventional (`feat:`, `fix:`, `chore:`, `test:`, `docs:`). Every user-visible change adds a line under `## [Unreleased]` in `CHANGELOG.md`.

## Review Focus

The spec is a vision document; these are the inputs it implies but does not spell out, most likely to bite a user first. Each has a test in the task that owns the code.

1. **Hostile or odd paths** — `../../etc/passwd`, `Auth/JWT`, `a//b`, `a/`, 600-character paths, `café`. A reasonable user expects a clear `invalid_path` error, never a 500 and never a write outside the project.
2. **Two clients upserting the same path at once** — a reasonable user expects one row whose content is one of the two writes, not a duplicate or a deadlock.
3. **Forged `X-Forwarded-For` from an untrusted peer** — a reasonable operator expects the allowlist and the recorded IP to reflect the real socket address.
4. **A session or API key revoked mid-request** — a reasonable user expects a 401 with nothing written.
5. **Inputs exactly at the documented limits** — a 256 KB body accepted and 256 KB + 1 byte rejected with a message naming the limit. (The 100-file ingest limit belongs to plan 2, where ingest lands.)

- [ ] **Step 4: Write `0002_security.sql`**

RLS, the access helper, and grants. Exact content:

```sql
ALTER TABLE projects       FORCE ROW LEVEL SECURITY;
ALTER TABLE memories       FORCE ROW LEVEL SECURITY;
ALTER TABLE project_grants FORCE ROW LEVEL SECURITY;
ALTER TABLE providers      FORCE ROW LEVEL SECURITY;

CREATE FUNCTION app_user_id() RETURNS uuid LANGUAGE sql STABLE AS $$
  SELECT nullif(current_setting('mimir.user_id', true), '')::uuid
$$;

-- projects: read if owner or any grant; write only for the owner
CREATE POLICY project_read ON projects FOR SELECT USING (
  owner_user_id = app_user_id()
  OR EXISTS (SELECT 1 FROM project_grants g
             WHERE g.project_id = projects.id
               AND g.principal_type = 'user'
               AND g.principal_id = app_user_id())
);
CREATE POLICY project_insert ON projects FOR INSERT WITH CHECK (owner_user_id = app_user_id());
CREATE POLICY project_update ON projects FOR UPDATE USING (owner_user_id = app_user_id());
CREATE POLICY project_delete ON projects FOR DELETE USING (owner_user_id = app_user_id());

-- memories: read follows project read; write needs a write grant
CREATE POLICY memory_read ON memories FOR SELECT USING (
  EXISTS (SELECT 1 FROM projects p WHERE p.id = memories.project_id
          AND (p.owner_user_id = app_user_id()
               OR EXISTS (SELECT 1 FROM project_grants g WHERE g.project_id = p.id
                          AND g.principal_type = 'user' AND g.principal_id = app_user_id())))
);
CREATE POLICY memory_write ON memories FOR ALL USING (
  EXISTS (SELECT 1 FROM projects p WHERE p.id = memories.project_id
          AND (p.owner_user_id = app_user_id()
               OR EXISTS (SELECT 1 FROM project_grants g WHERE g.project_id = p.id
                          AND g.principal_type = 'user' AND g.principal_id = app_user_id()
                          AND g.role = 'write')))
) WITH CHECK (true);

CREATE POLICY grant_read ON project_grants FOR SELECT USING (
  EXISTS (SELECT 1 FROM projects p WHERE p.id = project_grants.project_id
          AND (p.owner_user_id = app_user_id()
               OR EXISTS (SELECT 1 FROM project_grants g WHERE g.project_id = p.id
                          AND g.principal_type = 'user' AND g.principal_id = app_user_id())))
);
CREATE POLICY grant_modify ON project_grants FOR ALL USING (
  EXISTS (SELECT 1 FROM projects p WHERE p.id = project_grants.project_id
          AND p.owner_user_id = app_user_id())
) WITH CHECK (true);

CREATE POLICY provider_own ON providers FOR ALL
  USING (user_id = app_user_id()) WITH CHECK (user_id = app_user_id());

-- privileges: runtime role gets no DDL and no audit mutation
GRANT USAGE ON SCHEMA public TO mimir_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON
  users, sessions, api_keys, projects, project_grants, memories, providers, tokens,
  backup_runs, settings TO mimir_app;
GRANT INSERT, SELECT ON audit_log TO mimir_app;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO mimir_app;
```

Note in a comment that `memory_write` uses `FOR ALL` with `WITH CHECK (true)` deliberately: the `USING` clause already establishes project access, and the row's own `project_id` cannot change while preserving access.
