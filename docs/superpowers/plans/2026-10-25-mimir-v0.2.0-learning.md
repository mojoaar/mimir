# Mimir 0.2.0 — Learning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Mimir learn: per-user provider configuration, install-wide embeddings, background extraction of L0/L1, and a vector arm beside the existing keyword arm.

**Architecture:** pg-boss runs inside the Next.js process, started from `instrumentation.ts` after migrations, connected with the **owner** connection string because it creates its own `pgboss` schema. Jobs are durable rows in Postgres, so there is still one datastore and one backup. Provider calls go through one small OpenAI-compatible client (chat + embeddings + models) whose `fetch` is injectable, so every test runs without network. The write path embeds inline and never fails on a provider; extraction is debounced through a `short`-policy singleton job per project and only runs where `projects.learning_enabled` is true.

**Tech Stack:** Next.js 16 App Router, TypeScript strict, Postgres 17 + pgvector, `pg-boss` v10, Vitest, Tailwind v4.

**Spec:** `docs/superpowers/specs/2026-10-25-mimir-design.md` (§10 Learning pipeline, §11 Providers, §9 Retrieval)

## Global Constraints

- Postgres 17 + pgvector is the only datastore. No Redis, no second service.
- `memories.embedding` is `vector(768)` and stays 768. A model whose output is a different length is refused with an error naming the dimension, not silently truncated.
- One embedding model per installation, chosen by an admin, stored in `settings`. LLM providers are per user; extraction uses the **project owner's** key and never another user's.
- A write never fails because of a provider. Every provider call is wrapped; failure degrades to keyword search and a null column.
- Provider API keys are AES-256-GCM encrypted with `lib/crypto.ts`, stored only in `providers.api_key_enc`, and never printed, logged, or written to `audit_log` (audit uses the `api_key_hint` prefix at most).
- No test touches the network. Every provider function takes an optional `fetch`.
- Existing contracts stay: path rules, 256 KB body cap, one audit row per MCP/API call, error codes never carry driver text.
- Version stays `0.2.0` in `package.json`, `docker-compose.yml` image tag, and `CHANGELOG.md`.

## Review Focus

1. **A write with no embedding provider configured** stores the memory, leaves `embedding` null, and is immediately findable by keyword.
2. **A provider that times out, 500s, or returns garbage mid-write** does not lose the memory and does not return an error to the agent.
3. **A provider key never leaves the server**: not in page HTML after save, not in audit detail, not in logs — including when a request fails and the error is logged.
4. **One user's provider never serves another user's content**, and extraction on a project whose owner has no key does nothing rather than borrowing someone else's.
5. **The vector arm never degrades keyword search**: with `embedding` null on every row, or the embedding provider down, search still returns keyword results.
