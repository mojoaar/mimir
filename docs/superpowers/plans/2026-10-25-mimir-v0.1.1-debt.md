# Mimir v0.1.1 — Debt and Themes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clear the fourteen minor findings from the v0.1.0 review and put the Rimfrost theme system in place, so the admin UI in 0.3.0 is built once, on real tokens.

**Architecture:** Rimfrost's generated CSS is vendored verbatim under `styles/tokens/`; a hand-written `styles/theme.css` maps nine app-level aliases (`--bg`, `--fg`, `--border`, …) onto each theme's own ramp, so no component ever names a theme. The theme is a cookie resolved in the root layout into `<html data-theme>`, which means correct first paint. The debt fixes are local: one path parser, one prefix predicate, one error surface, one audit logger, one health endpoint.

**Tech Stack:** Next.js 16 App Router, TypeScript strict, Tailwind v4 (CSS-variable driven), Vitest, Postgres 17.

**Spec:** `docs/superpowers/specs/2026-10-25-mimir-design.md` (§17 UI/theming/SEO, §8 memory paths, §9 retrieval, §12 auth, §13 MCP, §15 HTTP API, §19 audit, §20 deployment)

## Global Constraints

- Themes come from `https://github.com/mojoaar/rimfrost` (MIT), vendored, never forked. Local clone: `/Users/mojoaar/Development/rimfrost/web/dist/tokens/`.
- Default theme `nordlys` with `nordlys-light` as its twin; eight values total: `fjord|nordlys|ravn|skumring` × `dark|light`.
- Theme is resolved server-side from a cookie. No `useEffect` swap, no flash of the wrong theme.
- `nordlys` dark is the default when the cookie is absent, unreadable, or names a theme that does not exist.
- Paths stay lowercase ASCII in `[a-z0-9._/-]`; `..` is rejected before any rewriting.
- No new runtime dependencies. `otpauth` is removed (it arrives with MFA in 0.3.0).
- Every error code crossing MCP or REST is one of: `invalid_path`, `invalid_params`, `body_too_large`, `not_found`, `forbidden`, `rate_limited`, `internal`.
- Next 16 conventions hold: `proxy.ts` not `middleware.ts`; `export const instant = false` on any page or layout that reads `cookies()` or `searchParams`; no route segment config in route handlers.
- `npm run typecheck` is run bare, never piped — a pipe hides tsc's exit status.
- Integration tests need the dev database: `./scripts/test-db.sh up` (127.0.0.1:5433).
- Commit style: conventional commits, one commit per task.

## Review Focus

Each line names an input class the spec implies but no existing test exercises. Each has its test placed in the task that owns the code.

1. A theme cookie holding junk (`"<script>"`, `"nordlys-light"` deleted from the code next year) renders the default theme, never unstyled HTML or a crash.
2. A path with unicode, whitespace or punctuation (`café`, `caf!`, `"   "`) fails loudly with `invalid_path` naming the character — it must never be rewritten into a neighbour's path and silently overwrite it.
3. A `path_prefix` containing `_` or `%` matches only that literal prefix, not a wildcard class of siblings.
4. Health with Postgres down reports failure (`503`) so the container healthcheck tells the truth, while the anonymous response still leaks neither version nor user.
5. An unknown email takes as long to reject as a wrong password (no account enumeration by timing).

- [ ] **Step 3: Rewrite `normalisePath`**

Order matters and is the security property: reject `..` on the raw string before anything is rewritten, then trim, then reject empty, then rewrite whitespace, then split on `/` and reject empty or `.` segments, then check the character class, then the length.

```ts
export function normalisePath(raw: string): string {
  if (typeof raw !== 'string') throw new InvalidPath('path must be a string')

  const lower = raw.toLowerCase()
  if (lower.includes('..')) throw new InvalidPath('traversal (..) is not allowed')

  const trimmed = lower.trim()
  if (trimmed === '') throw new InvalidPath('path is empty')

  const path = trimmed
    .replace(/\s+/g, '-')
    .replace(/\/{2,}/g, '/')
    .replace(/^\/+|\/+$/g, '')

  for (const segment of path.split('/')) {
    if (segment === '') throw new InvalidPath('path has an empty segment')
    if (segment === '.') throw new InvalidPath("path must not contain '.' segments")
  }

  const bad = path.match(/[^a-z0-9._/-]/)
  if (bad) throw new InvalidPath(`'${bad[0]}' is not allowed in a path (use a-z, 0-9, '.', '_', '/' or '-')`)
  if (path.length > MAX_PATH_LENGTH) {
    throw new InvalidPath(`path is ${path.length} characters, the limit is ${MAX_PATH_LENGTH}`)
  }
  return path
}
```

/**
 * The message must survive, or an operator cannot fix the failure; only the
 * credential-shaped parts of it are masked.

export function describeAuditFailure(error: unknown): string {
  const message = error instanceof Error ? error.message : String(error)
