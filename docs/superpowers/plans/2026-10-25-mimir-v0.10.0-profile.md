# 0.10.0 — Self-service account (profile, email, password, sessions) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a signed-in user edit their own name and email, change their own password, and see and revoke their own sessions — with no way to touch another account.

**Architecture:** A new `lib/users/self.ts` holds the self-service operations (the existing `lib/users/service.ts` stays admin-only, gated by `actorId`). Session listing/revocation primitives live in `lib/auth/session.ts` next to the existing session code. A new `/app/settings/profile` route renders forms backed by server actions, following the existing `ActionState` + KNOWN-code gate + redirect-outside-try pattern.

**Tech Stack:** Next.js 16 App Router, TypeScript strict, Postgres 18, Vitest, Tailwind v4 theme aliases.

**Spec:** `docs/superpowers/specs/2026-10-25-mimir-design.md` (§12 auth, §7 per-user settings surface).

## Global Constraints

- TypeScript strict with `noUncheckedIndexedAccess`; `npm run typecheck` must exit 0.
- Theme aliases only (`--fg`, `--bg-raised`, `--border`, `--accent`, `--danger`, `--text-muted`); never a palette class (`bg-white`, `text-red-500`, …). `styles/theme.test.ts` enforces this.
- Server actions live in `actions.ts` with `'use server'`; every page that reads the database declares `export const instant = false`.
- Server-action errors surface only messages from our codes (`invalid_params`, `forbidden`, `not_found`); anything else becomes a generic string. Redirects sit OUTSIDE the `try`.
- Passwords: argon2id via `hashPassword`/`verifyPassword` (`lib/auth/password.ts`); minimum `MIN_PASSWORD_LENGTH` (12) from `lib/auth/tokens.ts`.
- Integration tests seed only in `beforeEach` after `resetFixtures()`; fixtures are id STRINGS (`fixtures.alice`, `fixtures.aliceProjectId`, no `.id`).
- Audit every mutation through `lib/audit.ts` `audit(entry, tx?)` with namespaced actions; detail must never carry a password or email body.

## Review Focus

1. **A user can never touch another account.** A session id or email belonging to someone else must not change anything. → Task 2 test: `bob` cannot change `alice`'s email/password; Task 1 test: `revokeSessionById` scoped by `user_id` returns `false` for a foreign id.
2. **Email uniqueness is a message, not a 500.** Changing to an email that already exists (any case) must be refused as `invalid_params`. → Task 2 test asserts the `23505` maps to `'that email is already in use'`.
3. **Changing a password revokes other sessions but keeps the current one.** → Task 1/2 test: after `changePassword`, the current session still resolves and a second session is revoked.
4. **Email change requires the current password.** A wrong one must be refused with nothing written. → Task 2 test.
5. **The sessions list never leaks another user's sessions.** → Task 1 test: `listSessions(alice)` never contains a row whose `user_id` is not alice's, and `revokeOwnSession` refuses a session the caller does not own.

- [ ] **Step 3: Implement the four functions in `lib/auth/session.ts`**

Each runs `withService` and scopes by `user_id` (sessions are not under RLS, so the `where user_id = $1` is the only guard). `sessionIdFor` selects `id` where `token_hash = sha256(cookieValue)` and `revoked_at is null` and `expires_at > now()`. `listSessions` selects `id, ip, user_agent, last_seen_at, created_at` where `user_id = $1 and revoked_at is null and expires_at > now() order by created_at desc`. `revokeSessionById` updates `set revoked_at = now() where id = $1 and user_id = $2 and revoked_at is null` and returns `rowCount === 1`. `revokeOtherSessions` updates `set revoked_at = now() where user_id = $1 and id <> $2 and revoked_at is null`.

### Task 2: Self-service profile and password service

**Files:**
- Create: `lib/users/self.ts`
- Test: `lib/users/self.int.test.ts`

**Interfaces:**
- Consumes: `withUser` from `@/lib/db/tx`; `hashPassword`, `verifyPassword` from `@/lib/auth/password`; `MIN_PASSWORD_LENGTH` from `@/lib/auth/tokens`; `audit` from `@/lib/audit`; `listSessions`, `revokeOtherSessions` from `@/lib/auth/session` (Task 1).
- Produces (used by Tasks 3–4):
  - `type Profile = { id: string; email: string; name: string }`
  - `type ProfilePatch = { name?: string; email?: string; currentPassword?: string }`
  - `updateProfile(userId: string, patch: ProfilePatch): Promise<Profile>`
  - `changePassword(userId: string, current: string, next: string, currentSessionId: string): Promise<void>`
  - `type SessionSummary = { id: string; ip: string | null; userAgent: string | null; lastSeenAt: Date; createdAt: Date; current: boolean }`
  - `listMySessions(userId: string, currentSessionId: string): Promise<SessionSummary[]>`
  - `revokeOwnSession(userId: string, sessionId: string): Promise<void>`

- [ ] **Step 1: Write the failing tests**

In `lib/users/self.int.test.ts`, after `beforeEach` seeds via `resetFixtures()` + `seedTwoUsersWithProjects()` (fixtures are id STRINGS):
- `updateProfile` trims and saves a name, returns the new `name`.
- `updateProfile` with a new email and the correct current password returns the new `email`; the same email in a different case is also saved (citext).
- `updateProfile` with a new email and a WRONG current password rejects `invalid_params` and the email is unchanged (re-read via adminPool `select email::text from users where id = $1`).
- `updateProfile` with `email` set to `BOB@example.test` (bob's address, different case) rejects `invalid_params` `'that email is already in use'`.
- `changePassword` with a wrong `current` rejects `invalid_params` and the old hash still verifies.
- `changePassword` with `next` shorter than 12 rejects `invalid_params`.
- `changePassword` with the correct `current` and a 12-char `next` succeeds: the new password verifies, one `auth.password_change` audit row exists, a second session created before the change is revoked, and the current session (passed as `currentSessionId`) still resolves.
- `changePassword` for a user with `password_hash = null` rejects `invalid_params` naming the reset link.
- `listMySessions` marks the row whose id equals `currentSessionId` with `current: true` and all others `false`.
- `revokeOwnSession` revokes a session the user owns; a session id belonging to bob throws `not_found` (or resolves to a no-op that leaves bob's session intact).

- [ ] **Step 2: Run to verify they fail**

Run: `npm run test:int -- lib/users/self`
Expected: FAIL — `Cannot find module '@/lib/users/self'`.

- [ ] **Step 3: Implement `lib/users/self.ts`**

`updateProfile` runs `withUser(userId, …)` and builds the UPDATE from which of `name`/`email` is present; `name` is trimmed and must be non-empty and ≤ 200 chars; `email` is trimmed and must contain `@`, and its change requires a correct `currentPassword` (verified against the stored hash first). A `23505` on the email update maps to `fail('invalid_params', 'that email is already in use')`. Audit `auth.profile_update` with `detail: { changed }` (`'name'` or `'email'`, never the values). `changePassword` runs one `withUser` transaction: select `password_hash` (null → `fail('invalid_params', 'you have not set a password yet; use a reset link')`), `verifyPassword` the current hash (false → `fail('invalid_params', 'your current password is wrong')`), enforce `next.length >= MIN_PASSWORD_LENGTH`, `hashPassword(next)`, update, `revokeOtherSessions(userId, currentSessionId)`, and audit `auth.password_change`. `listMySessions` maps `listSessions(userId)` to `SessionSummary` adding `current: id === currentSessionId`. `revokeOwnSession` calls `revokeSessionById` and throws `fail('not_found', 'that session is gone')` when it returns false. Add a private `fail(code, message)` returning `Error & { code }` matching `lib/users/service.ts`.
